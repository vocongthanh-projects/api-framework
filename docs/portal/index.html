Quy tắc chuẩn bất khả xâm phạm (Core Standards)

QUY TẮC SỐ 1: TUYỆT ĐỐI KHÔNG HARDCODE
Không được hardcode URL môi trường, IP, domain, username, password, token trong source code hay file properties. Mọi cấu hình phải lấy qua System Properties (`-D`), Biến môi trường hoặc `config-local.properties` (được ignore trên git).
Quy tắcLý do & Cách áp dụng
Không dùng `RestAssured.given()` trực tiếpMọi request phải đi qua `ApiClient` để đảm bảo được ghi trace, tự động retry an toàn và che giấu secret.
Không dùng `Thread.sleep` đứng imDùng `Eventually` trong `framework-fixtures` để kiểm tra theo điều kiện (polling), giúp test chạy nhanh hơn 50-80%.
Dọn rác dữ liệu ngay sau khi tạoSử dụng `ResourceLedger` để đăng ký hành động cleanup theo cơ chế LIFO (tạo trước - xóa sau cùng).

1. API Automation — RestAssured Framework

framework-*

Framework API được đóng gói thành 4 module độc lập phát hành trên GitLab Package Registry: framework-core, framework-http-restassured, framework-fixtures, và framework-testng.

1.1 Khai báo `pom.xml` trong dự án Consumer

Mở file pom.xml trong dự án test của bạn (như api-map, api_hrm) và thêm kho thư viện GitLab + dependencies:

pom.xml
<!-- 1. Khai báo kho GitLab Package Registry -->
<repositories>
    <repository>
        <id>gitlab-maven</id>
        <url>http://10.0.0.40/api/v4/groups/qc-quality-control/-/packages/maven</url>
    </repository>
</repositories>

<properties>
    <framework.version>1.0.0-SNAPSHOT</framework.version>
</properties>

<dependencies>
    <!-- Vòng đời TestNG, TestContext & Tracing -->
    <dependency>
        <groupId>vn.ots.qc</groupId>
        <artifactId>framework-testng</artifactId>
        <version>${framework.version}</version>
    </dependency>

    <!-- Động cơ HTTP RestAssured (Tự retry, che giấu mật khẩu, tự refresh 401) -->
    <dependency>
        <groupId>vn.ots.qc</groupId>
        <artifactId>framework-http-restassured</artifactId>
        <version>${framework.version}</version>
    </dependency>

    <!-- Tiện ích tạo data ngẫu nhiên UniqueData, Eventually, ResourceLedger -->
    <dependency>
        <groupId>vn.ots.qc</groupId>
        <artifactId>framework-fixtures</artifactId>
        <version>${framework.version}</version>
    </dependency>
</dependencies>

1.2 Khởi tạo Base Test (`createRuntime()`)

Kế thừa BaseApiTest và implement cấu hình một lần duy nhất cho toàn bộ dự án:

BaseProjectApiTest.java
public abstract class BaseProjectApiTest extends BaseApiTest {
    protected UserClient userClient;

    @Override
    protected ApiTestRuntime createRuntime() {
        FrameworkConfig config = FrameworkConfig.builder()
                .service(ServiceConfig.builder("userService", Config.getBaseUrl())
                        .authProfile("admin")
                        .header("Content-Type", "application/json")
                        .build())
                .build();

        CredentialManager credentials = new CredentialManager(Map.of(
                "admin", actor -> AuthMaterial.bearer(loginAndGetToken(actor), Instant.now().plusSeconds(3600))
        ));

        ApiClient api = new RestAssuredApiClient(config, credentials, new CurrentTestTraceSink());
        userClient = new UserClient(api);

        return new ApiTestRuntime(config, credentials, api);
    }
}

1.3 Tạo Domain Client & Test Case

Tách biệt tầng Client (chỉ chứa endpoint) và tầng Test (chứa logic kiểm thử):

UserClient.java & UserApiTest.java
// 1. DOMAIN CLIENT: Chỉ nhận ApiClient và bắn request
public class UserClient {
    private final ApiClient api;
    public UserClient(ApiClient api) { this.api = api; }

    public ApiResponse getUserDetail(Actor actor, String userId) {
        return api.execute(ApiRequest.get("userService", "/api/v1/users/" + userId)
                .actor(actor)
                .build());
    }
}

// 2. TEST CASE: Kế thừa BaseProjectApiTest
public class UserApiTest extends BaseProjectApiTest {
    @Test
    public void testGetUserSuccess() {
        Actor admin = Actor.of("admin_user", "admin");
        context().actor(admin);

        ApiResponse res = userClient.getUserDetail(admin, "U123");
        res.requireStatus(200); // Tự động throw lỗi kèm trace nếu status code khác 200

        Assert.assertEquals(res.json().path("data.status").asText(), "ACTIVE");
    }
}

2. Web Automation — Microsoft Playwright

PLAYWRIGHT (Java)

Microsoft Playwright là framework kiểm thử Web hiện đại nhất hiện nay: Tự động đợi phần tử (Auto-wait), chạy đa luồng cực nhanh, ghi trace/video và hỗ trợ đầy đủ Chromium, Firefox, WebKit.

2.1 Khai báo Dependency Playwright

pom.xml
<dependency>
    <groupId>com.microsoft.playwright</groupId>
    <artifactId>playwright</artifactId>
    <version>1.49.0</version>
    <scope>test</scope>
</dependency>

2.2 Base Web Test & Khởi tạo Playwright

BaseWebTest.java
public abstract class BaseWebTest {
    protected static Playwright playwright;
    protected static Browser browser;
    protected BrowserContext context;
    protected Page page;

    @BeforeSuite
    public void setupSuite() {
        playwright = Playwright.create();
        boolean headless = Boolean.parseBoolean(System.getProperty("headless", "true"));
        browser = playwright.chromium().launch(new BrowserType.LaunchOptions().setHeadless(headless));
    }

    @BeforeMethod
    public void setupMethod(Method method) {
        context = browser.newContext(new Browser.NewContextOptions().setViewportSize(1920, 1080));
        // Bật ghi hình Trace Viewer
        context.tracing().start(new Tracing.StartOptions().setScreenshots(true).setSnapshots(true));
        page = context.newPage();
    }

    @AfterMethod
    public void tearDownMethod(ITestResult result) {
        if (!result.isSuccess()) {
            // Lưu Trace file khi test fail để mở xem lại
            context.tracing().stop(new Tracing.StopOptions().setPath(Path.of("target/traces/" + result.getName() + ".zip")));
        }
        context.close();
    }

    @AfterSuite
    public void tearDownSuite() {
        browser.close();
        playwright.close();
    }
}

2.3 Page Object Model (POM) & Locators chuẩn

Tuyệt đối tránh dùng XPath tuyệt đối hoặc ID dễ đổi. Hãy dùng Locators hướng người dùng (User-facing locators):

LoginPage.java & WebLoginTest.java
// 1. PAGE OBJECT MODEL
public class LoginPage {
    private final Page page;

    public LoginPage(Page page) { this.page = page; }

    public void navigate() { page.navigate(Config.getBaseUrl() + "/login"); }

    public void login(String username, String password) {
        // Playwright khuyến khích getByRole, getByPlaceholder, getByLabel
        page.getByPlaceholder("Tên đăng nhập").fill(username);
        page.getByPlaceholder("Mật khẩu").fill(password);
        page.getByRole(AriaRole.BUTTON, new Page.GetByRoleOptions().setName("Đăng nhập")).click();
    }

    public Locator getErrorMessage() {
        return page.locator(".alert-danger");
    }
}

// 2. TEST CLASS
public class WebLoginTest extends BaseWebTest {
    @Test
    public void testLoginWithInvalidPassword() {
        LoginPage loginPage = new LoginPage(page);
        loginPage.navigate();
        loginPage.login("thanhvc", "sai_mat_khau");

        // Playwright Assertions tự động chờ phần tử xuất hiện
        assertThat(loginPage.getErrorMessage()).isVisible();
        assertThat(loginPage.getErrorMessage()).containsText("Sai mật khẩu");
    }
}

3. Mobile Automation — Appium 2.x (Android & iOS)

APPIUM 2.X

Appium 2.x là giải pháp kiểm thử đa nền tảng cho ứng dụng di động Native & Hybrid, sử dụng driver UiAutomator2 cho Android và XCUITest cho iOS.

3.1 Khai báo Appium Java Client

pom.xml
<dependency>
    <groupId>io.appium</groupId>
    <artifactId>java-client</artifactId>
    <version>9.4.0</version>
    <scope>test</scope>
</dependency>

3.2 Cấu hình Driver cho Android & iOS

BaseMobileTest.java
public abstract class BaseMobileTest {
    protected AppiumDriver driver;

    @BeforeMethod
    public void setupMobileDriver() throws MalformedURLException {
        String platform = System.getProperty("platform", "android").toLowerCase();
        URL appiumServer = new URL(System.getProperty("appium.url", "http://127.0.0.1:4723"));

        if (platform.equals("android")) {
            UiAutomator2Options options = new UiAutomator2Options()
                    .setDeviceName("Pixel_7_Pro")
                    .setApp(System.getProperty("app.path"))
                    .setAutomationName("UiAutomator2")
                    .autoGrantPermissions();
            driver = new AndroidDriver(appiumServer, options);
        } else {
            XCUITestOptions options = new XCUITestOptions()
                    .setDeviceName("iPhone 15 Pro")
                    .setApp(System.getProperty("app.path"))
                    .setAutomationName("XCUITest")
                    .setAutoAcceptAlerts(true);
            driver = new IOSDriver(appiumServer, options);
        }
    }

    @AfterMethod
    public void tearDownMobileDriver() {
        if (driver != null) driver.quit();
    }
}

3.3 Thao tác Vuốt màn hình chuẩn W3C Actions

Trong Appium 2.x, TouchAction cũ đã bị loại bỏ hoàn toàn. Thay vào đó, sử dụng W3C Pointer Actions:

MobileGestures.java
public final class MobileGestures {
    public static void swipeUp(AppiumDriver driver) {
        Dimension size = driver.manage().window().getSize();
        int startX = size.width / 2;
        int startY = (int) (size.height * 0.8);
        int endY = (int) (size.height * 0.2);

        PointerInput finger = new PointerInput(PointerInput.Kind.TOUCH, "finger");
        Sequence sequence = new Sequence(finger, 1)
                .addAction(finger.createPointerMove(Duration.ZERO, PointerInput.Origin.viewport(), startX, startY))
                .addAction(finger.createPointerDown(PointerInput.MouseButton.LEFT.asArg()))
                .addAction(finger.createPointerMove(Duration.ofMillis(600), PointerInput.Origin.viewport(), startX, endY))
                .addAction(finger.createPointerUp(PointerInput.MouseButton.LEFT.asArg()));

        driver.perform(Collections.singletonList(sequence));
    }
}

3.4 Mobile Page Object (Dùng chung cho cả Android và iOS)

MobileLoginPage.java
public class MobileLoginPage {
    private final AppiumDriver driver;

    @AndroidFindBy(id = "vn.ots.maps:id/edt_username")
    @iOSXCUITFindBy(accessibility = "input-username")
    private WebElement usernameInput;

    @AndroidFindBy(id = "vn.ots.maps:id/edt_password")
    @iOSXCUITFindBy(accessibility = "input-password")
    private WebElement passwordInput;

    @AndroidFindBy(id = "vn.ots.maps:id/btn_login")
    @iOSXCUITFindBy(accessibility = "btn-submit")
    private WebElement loginButton;

    public MobileLoginPage(AppiumDriver driver) {
        this.driver = driver;
        PageFactory.initElements(new AppiumFieldDecorator(driver, Duration.ofSeconds(10)), this);
    }

    public void login(String user, String pass) {
        usernameInput.sendKeys(user);
        passwordInput.sendKeys(pass);
        loginButton.click();
    }
}

4. CI/CD Pipeline Template cho GitLab

Mẫu cấu hình GitLab CI để chạy kiểm thử tự động trên CI Runner có sẵn JDK 17:

.gitlab-ci.yml
image: eclipse-temurin:17-jdk

stages:
  - test
  - report

api_tests:
  stage: test
  script:
    - chmod +x mvnw
    - ./mvnw test -Dgroups="smoke" -Dbase.url="$STAGING_API_URL"
  artifacts:
    when: always
    reports:
      junit: target/surefire-reports/TEST-*.xml
    paths:
      - target/api-traces/

web_playwright_tests:
  stage: test
  image: mcr.microsoft.com/playwright/java:v1.49.0-jammy
  script:
    - ./mvnw test -Dtest=WebLoginTest -Dheadless=true
  artifacts:
    when: on_failure
    paths:
      - target/traces/
